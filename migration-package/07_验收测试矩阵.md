## 第二部分：业务测试（必须）

### A. 标准 Fast Quote

- 给定足够且已确认的业务/水力/电气参数；Route = `fast_quote`。
- 跟踪 `inquiry → fast_selection → technical_package → validation → engineering_cost → commercial → pi`。
- **断言 0 次 JiuwenSwarm 调用**，不应为普通询盘耗费 Team Token。
- 标准机型仅输出 1 个主推荐，但可以保留备选分析供人看。

### B. 复杂 Expert Quote

- 提供已确认水头/流量/容量等，增加经批准复杂度规则命中的季节流量、泥沙或专业运行场景；Route = `expert_quote`。
- 4 个独立角色真实分析，再讨论和交叉审核；输出合同有效的 Technical Selection Package。
- LangGraph 再做水力、机型配置、Schema 和技术风险核验，需人工则暂停。**只在验证通过或人工批准后才进入成本流程**。
- 注入 Team 超时/不存在/不返回 JSON/某专家缺席，必须失败或人工复核，不得自动伪造 Fast 结果。

### C. 缺参数

- 仅 2MW、缺净水头和设计流量 → `needs_input`，不中途进入 Swarm/报价。
- 客户 revise 后检查 resume 的同一个 quote_id/thread，且不重复创建 invoice。

### D. 五设备并行和定价

- 必须存在 **五项**：Hydro Turbine、Generator and Exciter/AVR、Speed Governor、Inlet Valve、Automation System。
- 输入 1200kW × 2 Francis，水轮机单项底价 = USD 108,000（每台 54,000）；这 **不是整个工程成本或商业报价**。
- 价格合计只计一次；重复计算同一 request/rule_version 返回一致金额。
- 未批准 Risk Reserve Rate、原报价规则的价格段只有范围无具体系数、单台大于 5000kW、输入设备配置矛盾等 → `review_required`，不可擅自给 Firm Quote。
- 原规则 1500kW 人员成本示例有 `USD 3,000` 与公式矛盾：保留歧义清单，不能悄悄套用 3,000。

### E. 商业和 PI

- 核实 `CommercialQuotation = InternalCost × 2.40`。
- PI 表单的客户、银行、付款、交付、HS 编码、保证条款如未提供不得伪造。
- 未通过风险、人工或客户确认时，允许生成标记 Preliminary 的说明，但不签发 Firm PI。
- 只有授权访问能下载报价文件，PI 总价必须等于客户报价汇总。

## 第三部分：MCP 与权限

- `/mcp` Server 对外 Tool 数量 = 1，名称完全匹配 `hydroquote_quote`。
- 外部 MCP Client 可以 `list_tools`, `call_tool(create)`, `call_tool(get)`。
- 未授权认证、其他租户报价、没有 `review:write` 的 `submit_review` 应失败。
- `get` 给 reviewer 的技术字段符合最小授权原则，不返回采购成本、内部利润率、真实凭证。
- 缺乏真实模型/API 权限时 mock 可用于离线测试，但必须把 **真实集成运行** 标为 blocked，不能造证据。

## 第四部分：技术治理

- 使用 LangGraph 真实 Checkpointer 的 thread_id，至少一次中断/恢复。
- Agent Core `WorkflowAgent.invoke` 在真实请求路径运行。
- JiuwenSwarm `--mode team` 实际触发四角色，日志与 quote_id 关联。
- 五设备是否真的并行要有执行 trace；只写 Python 五个函数不算并行完成。
- CLI Team 同一 `/tui` channel 禁止无控制地并行多调用；队列/隔离可验证。
- `README.md` 更新为 LangGraph 总控；旧 Prompt-only 文档标记 Legacy/Deprecated，避免同时存在两套自相矛盾的架构说明。
- 前端上传、文本输入、询盘补参、技术方案、报价展示、PI 下载完整回归。
